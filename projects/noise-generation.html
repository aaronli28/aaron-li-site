Quantifying Noise in Language Generation

Aaron Li · Ian Zhang
arXiv ↗ PDF ↓
How much does noise in the training data change what a language-generating algorithm can learn? We study this in the Kleinberg–Mullainathan generation-in-the-limit framework and prove two complementary results: a single noisy string is enough to strictly shrink the set of generatable collections — yet any finite amount of noise is no worse than just one.
Background

A game between an adversary and an algorithm

Kleinberg & Mullainathan (2024) introduced a clean model for studying language generation. There's a known collection $\mathcal{C}$ of candidate languages over some universe $\mathbb{Z}$. An adversary secretly chooses one language $K \in \mathcal{C}$ and starts enumerating its elements. After each reveal, the algorithm must guess a new string — ideally one that's also in $K$.

Scroll down to watch a round play out.

01 — The setup

The model

Two players: an adversary who knows the target language $K$, and an algorithm trying to learn it. The adversary reveals strings one at a time; the algorithm must respond with a new guess each round.

02 — Move 1

Adversary reveals $x_0$

The adversary outputs the first element of $K$. The algorithm sees $x_0$ and must respond.

03 — Move 2

Algorithm guesses $z_0$

Now it's the algorithm's turn. It outputs $z_0$ — some string it hasn't seen yet, hoping $z_0 \in K$.

04 — Mistakes

Wrong guesses are allowed

The algorithm might output an incorrect guess — $z_0$ doesn't have to be in $K$. Early errors are expected. What matters is that eventually, all guesses land in $K$.

05 — Many rounds

The dance continues

Round after round: adversary reveals one more element of $K$, algorithm guesses one new string. The two interleave forever.

06 — Convergence

Generatable in the limit

If there exists a finite time $t^\star$ after which every algorithm guess is in $K$, we say $\mathcal{C}$ is generatable in the limit. The algorithm never knows it's reached $t^\star$ — but from that moment on, its output is reliably correct.

07 — Noise

What if the adversary cheats?

In the noisy generation setup, the adversary is also allowed to make mistakes — to insert strings that aren't in $K$. Here, $x_2$ is noise. The algorithm can't tell which strings are real and which are junk, but it must still generate from $K$ in the limit.

Results

What we prove

Theorem 1 · Separation

One noisy string strictly hurts.

For both uniform and non-uniform generation, there exist collections that are generatable without noise but become impossible to generate as soon as the adversary can insert even a single string outside $K$. This answers an open question of Raman & Raman (2025) in the negative — noise is not a smooth degradation, it's a sharp cliff.

Theorem 2 · Collapse

One noisy string $\equiv$ any finite amount.

Once you can tolerate one noisy string, you can tolerate any finite amount. Uniform generation with noise level $1$ is equivalent to uniform generation at every finite noise level $i \geq 1$, and the same holds non-uniformly. This contrasts sharply with the strict hierarchy that does appear for generation in the limit (Bai, Panigrahi, & Zhang, 2026).

Theorem 3 · Characterization

A combinatorial criterion.

Building on the equivalence above, we give the first known characterization of non-uniform noise-dependent generatability in terms of an extension of the closure dimension.
